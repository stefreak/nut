# Implementation Plan: Core Library Foundation

**Branch**: `001-core-library-foundation` | **Date**: 2026-02-12 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-core-library-foundation/spec.md`

## Summary

Refactor nut repository to establish core-first architecture per constitution. Extract workspace management, config, and directory operations from CLI into new `nut-core` crate. CLI becomes thin adapter over core. Add Tauri backend exposing core via typed commands. Generate TypeScript types for Rust↔TypeScript boundary. Implement UI for create/list workspaces and import repositories.

## Technical Context

**Language/Version**: Rust Edition 2024  
**Primary Dependencies**: clap 4.x (CLI), Tauri 2.x (desktop), tokio 1.x (async), octocrab (GitHub API), ulid (IDs), specta + tauri-specta (type generation)  
**Storage**: Filesystem (workspace directories, `.nut.json` config), bare git repos in cache  
**Testing**: cargo test, integration tests in `tests/`  
**Target Platform**: macOS, Linux (desktop + CLI)  
**Project Type**: Hybrid workspace (core library + CLI binary + Tauri app)  
**Performance Goals**: <500ms workspace list, <1s workspace creation, <2s app launch  
**Constraints**: CLI behavior must not change, zero breaking changes for existing users  
**Scale/Scope**: ~10-50 workspaces per user, ~100 repos per workspace typical

## Constitution Check

✅ **I. Core-First Architecture**: This feature establishes the pattern—core library created first  
✅ **II. Type Safety Across Boundaries**: specta with tauri-specta for Rust→TypeScript generation  
✅ **III. Security by Design**: Tauri permissions scoped to workspace dirs, tokens not exposed to frontend  
✅ **IV. Simplicity & Iteration**: Minimal scope—only create/list/import, exact CLI parity  
✅ **V. Performance & Responsiveness**: Async operations, progress callbacks for UI

No violations. Constitution principles guide the architecture.

**Structure Decision**: Cargo workspace with three crates:
1. **nut-core**: Shared library (no CLI deps)
2. **nut-cli**: Binary using core (thin adapter)
3. **src-tauri**: Tauri app using core (commands layer)

Existing `src/` directory will be split and removed. `user-interface/` gets Tauri integration.

## Implementation Strategy

### Phase 1: Core Library Foundation
- Create `crates/nut-core` with moved code from `src/`
- Remove CLI-specific code (enter, apply, status remain in CLI)
- Add integration tests for core

### Phase 2: CLI Refactoring
- Create `crates/nut-cli` 
- Update main.rs to use core library
- Verify existing tests pass
- Keep `enter`, `apply`, `status` in CLI only

### Phase 3: Tauri Backend
- Initialize `src-tauri/` with Tauri 2.x
- Create commands wrapping core library
- Configure capabilities for filesystem access
- Setup type generation (specta/ts-rs)

### Phase 4: Frontend Integration
- Generate TypeScript types from Rust
- Update services to invoke Tauri commands
- Connect UI components to Tauri backend
- Test end-to-end create/list/import

## Migration Path

Existing CLI users experience zero breaking changes. New Tauri UI provides alternative interface but doesn't replace CLI workflows (enter, apply remain CLI-only by design).
